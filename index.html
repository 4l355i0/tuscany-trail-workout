Zwift ZWO

Zwift conversion uses the selected FTP: Power = target watts / FTP. FTP does not alter the physical route scaling.

1. Physical route model

P = v / η × [ m g sin(θ) + m g Crr cos(θ) + ½ ρ CdA v² ]

The route first determines absolute power demand. FTP is not part of this physics.

2. Selective route scaling

For work blocks: Pnew = P75 × (Scale / 75)
For artificial recovery blocks: Precovery = 85 W

Only meaningful route-derived work changes with the scaling factor. Recovery placeholders created during compression do not become harder when the simulation factor rises.

3. FTP is separate

PowerZWO = Ptarget / FTPuser
IF = NP / FTPuser
TSS = hours × IF² × 100

FTP changes how hard the same absolute-watt workout is for a rider and how Zwift encodes it. It does not redefine the route scaling factor.

4. Example

If a work block is 120 W at 75%:

90% simulation → 120 × 90/75 = 144 W

If the adjacent recovery block is 85 W, it remains 85 W at 75%, 90% and 100%.
